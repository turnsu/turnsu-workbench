# Skill OS 与 Loop

Skill OS 帮助用户找到、使用和沉淀可复用的方法。方法服务于当前项目和任务，不要求先理解执行引擎。

## Skill

读取项目中已有的 Skill，确认说明、来源、版本和所需权限，再在新任务中使用。也可以从已完成任务的实际回答创建方法草稿，检查文件与依赖后试用。保存方法不等于验证成功；安装与发布使用固定内容和版本。

项目文件和私有会话属于本机。向团队发布前必须核对要分享的文件与结果，不自动上传完整会话、隐藏上下文或凭据。云端状态不确定时查询已有回执，不能重复执行任务来补回执。

## Loop

Loop 是带顺序和依赖的重复方法。默认只显示名称、输入、步骤和结果。用户先试跑，再检查输出和失败位置，最后保存或发布版本。高级依赖与图形配置按需使用，不成为日常任务的前置步骤。

继续保留版本固定、停止 / 恢复、权限、安装一致性和结果核验。精简界面不能取消这些保障。新项目不预装行业业务样例。

## 客户适配的扩展边界

本地版先让员工在项目中使用、整理和试跑 Skill。客户需要团队级能力包时，可另行组合经审核的 Skill、连接器与配置；这不阻挡普通本地任务。客服方法可以引用已选微信材料；只有接入并授权真实订单工具后才能引用其结果。方法本身不能获取新权限、决定退款额度或自动发送消息。

现有原生 Skill 导出只适合已通过检查的指令包；带 runtime、工具、依赖、可执行文件或隐藏原生配置的内容会被拒绝。新增连接器走独立的受控安装和运行绑定，不删除这层拒绝条件。能力包需固定版本、检查依赖与权限、支持试跑及回退；运行中的事项不被静默升级。

方法还需声明所需能力、已验证 Agent / 版本和专属工具绑定，不能默认所有执行都由 Pi 完成。纯指令可复用不代表工具、批准、历史或附件能力兼容；按实际适配结果显示可用范围。切换执行 Agent 前检查依赖与授权，试跑绑定实际执行器和模型来源。任务交接保留同一方法的版本与已有结果，但不转移原生账号、私有会话或隐藏上下文。
