# 工作流创建与调整：交互复查

日期：2026-09-22。范围：既有工作流编辑器；不替代 Skill 存储和原生 Agent 接入的架构调研。

## 结论与依据

采用「画布为主，选中才配置，按需添加，结果就地查看」。流程的空间关系和直接操作是用户要保留的能力；把画布藏在高级入口、用完整填写页替代编辑会提高调整成本。

| 参考 | 实际证据 | 用于本次设计的判断 |
| --- | --- | --- |
| [Dify 官方快速开始](https://docs.dify.ai/en/quick-start) | 官方教程与节点配置截图；浏览器查看了官方图。创建后进入画布，点击节点配置变量，再测试结果。 | 画布承载全局关系，侧栏承载局部设置；编辑和验证放在同一个工作区。 |
| [n8n AI workflow builder](https://docs.n8n.io/build/ways-of-building-workflows/ai-workflow-builder) | 官方说明支持自然语言创建、修改和调试，同时要求用户核对生成流程、凭据及参数。 | AI 辅助与可检查的流程结构可以共存；不能用未接通的聊天面板取代可操作的编辑器。 |
| 用户提供的旧画布、当前 Turnsu 实际页面 | 本地已登录的 PostgreSQL 工作流：旧界面重复标题、常驻技能栏和底部表单挤压画布；填写页则隐藏了依赖的空间关系。 | 保留画布直接调整的优点，收起常驻配置，统一保存与试运行入口。 |

这是官方资料与当前产品的针对性对照，不是竞品账号内的完整可用性测试，也没有据此推断市场使用率。Gumloop 历史文档链接已重定向，因此不将其旧版 checkpoint 行为作为本轮实现依据。

## 具体迭代

- 一层标题与动作：返回、保存状态、撤销/重做、保存、试运行。
- 画布直接显示真实节点及输入/输出端口。点击输出再点目标输入建立绑定；可选中连线删除，缺少必要输入就地提示。
- 添加步骤时才打开可搜索的技能/资料库；选中节点才展示名称、指令、输入来源及复核/模型选项。
- 保留拖动、平移、缩放、适配视图，并提供只改坐标的一键整理。侧栏打开时保持可读比例，选中节点居中。
- 撤销恢复整个草稿，包括端口绑定、节点位置和运行输入字段。服务端版本及 ETag 不随撤销倒退。
- 试运行侧栏使用真实 Product 命令与 Run 查询，显示步骤状态、失败、Markdown 结果及历史记录。未保存时先保存当前修订，再编译、运行该修订。
- 保存与运行状态直接反馈在编辑器，移除遮挡侧栏操作的重复成功提示；失败提示仍保留恢复入口。

## 验收与边界

已在本地隔离 PostgreSQL 实例和真实浏览器操作三步私有 Skill 流程，验证连线删除/重连、撤销/重做、保存后撤销、布局刷新恢复，以及删除输入节点后运行表单去除对应字段。自动回归保护完整草稿恢复、保存与查询竞态、连接类型/循环约束和布局不改执行关系。

桌面 1280×720 已目测并实际拖动节点、打开配置、切换历史记录；以前成功运行的 Markdown 结果能在新侧栏重新读取，并标为之前版本。模型设置已区分控制模型/图片模型，空值正确显示继承默认值。构建、编辑器、路由、API 客户端、模型选择、运行流及前端边界检查通过。视口工具的 390×844 设置未实际作用于页面，观测仍为 1280×720；移动端响应式代码已提供，但本轮未完成真实窄屏验收，不报告移动端通过。

本轮两次新试运行已进入真实模型调用，均返回 `provider_request_invalid`；新旧调用的 Skill 请求输入、输出合同、模型修订一致。页面显示失败并保留输入供重试。这里不把已启动当作成功，也不以历史完成记录代替本轮成功执行。

本轮没有增加 AI 编排聊天框、原生 CC/Codex/Pi 选择器或假运行结果。用户自带 Agent 是既有产品方向，仍需其独立的会话、授权和连接实现；它不改变本次画布保存与依赖绑定的 Product 权威边界。
