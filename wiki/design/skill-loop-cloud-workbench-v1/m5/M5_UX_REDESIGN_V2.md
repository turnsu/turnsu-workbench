## 0. 原则

沿用方案 A 的交互结构与信息架构，配色采用 r8 新 token（暖米白底、单一靛蓝强调、
light-first、行结构优先），不引入第二套视觉系统。产品语义、路由、数据所有权、
bundle 拆分、Draft/proposal 控制链全部不变。本方案只补四件事：**层级、控件、空态、
动线**。

- `DESIGN_VARIANCE: 4`、`MOTION_INTENSITY: 2`、`VISUAL_DENSITY: 6` 维持不变；
- 每屏**只有一个 primary 按钮**；取消/返回一律 tertiary；
- 卡片只承载独立对象，分区用标题 + 分隔线，禁止卡片套卡片与双标题；
- 状态不只靠颜色表达；每个错误一个原因 + 一个恢复动作；
- **界面文案说人话**：工程词不进界面（第 8 节）。

## 1. P0 · 全局设计体系（对应帧 00）

### 1.0 配色方案（r8 全面更新）

旧方案"冷灰底 + 高饱和默认蓝（#2457e6）"是简陋感的主要来源。新方案对齐当前主流
（Linear、Notion、Stripe、Arc 的共同方向：暖中性底 + 低饱和墨色 + 单一精致 accent +
柔和边线）：

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底 | `#f7f6f3` | 暖米白（取代冷灰 `#f4f6f9`） |
| 表面 | `#ffffff` / `#faf9f7` | 卡片与浅分区 |
| 墨色 | `#1b1917` / `#44403c` | 暖黑，不用纯黑 |
| 次级文字 | `#78716c` / `#a8a29e` | 说明与占位 |
| 边线 | `#eceae6` / `#ddd9d3` | 更浅更柔，卡片不再"描黑边" |
| 主色 | `#4f46e5` / hover `#4338ca` | 靛蓝（取代高饱和蓝） |
| 主色浅底 | `#eef0ff` / `#c7d2fe` | 选中态、聚焦环 |
| 成功 | `#047857` / `#d1fae5` | 低饱和绿 |
| 警告 | `#b45309` / `#fffbeb`+`#fde68a` | 琥珀 |
| 危险 | `#b91c1c` / `#fef2f2` | 柔红 |
| 共享紫 | `#7c3aed` / `#f5f3ff` | 已发布共享 |
| 阴影 | `rgb(28 25 23 / .06–.16)` | 暖调，不用冷蓝灰影 |
| 深色 | `#1c1917` 底 / `#292524` 面 | 暖黑同族，不做简单反色（帧 19） |

规则：accent 全站只此一个；状态色一律低饱和；聚焦环 `0 0 0 4px rgb(79 70 229/.10)`。

### 1.1 按钮

| 级别 | 样式 | 用途 |
|---|---|---|
| primary | 靛蓝实心 `#4f46e5`，hover `#4338ca` | 每屏唯一主动作（发送、保存草稿、运行、发布） |
| secondary | 白底描边 `#d0d5dd` | 页面次动作（上传、重试、安装、编辑、下载） |
| tertiary | 无边框蓝字 | 返回、取消、查看、展开、重命名 |
| danger-ghost | 红字透明底 | 放弃提案、删除 |

- **黑色实心按钮移出体系**（原 Loops 页 4 个黑按钮、Back to Skills 黑按钮全部改级）。
- 禁用态必须附原因：tooltip 或按钮旁 inline hint，全站二选一，不混用。
- 高度 34px（列表内 30px），圆角 8px，字号 12.5px/600。

### 1.2 表单控件

- 输入框：可见边框 `#ddd9d3`、圆角 8、白底、高 38px；聚焦 = 靛蓝边 + 4px 浅环
  `0 0 0 4px rgb(79 70 229/.10)`；标签在上，帮助/错误文本在下 4px。**禁止裸标签无框**。
- 原生控件全部替换：`select`→自定义 dropdown；`number`→自定义 stepper；
  `file`→统一 dropzone（点击或拖拽，**全站每屏只有一个文件选择入口**）。
- segmented control 用于模式/类型切换（文本/图像、技能类型过滤）。
- JSON 编辑区：固定高度 ~120–160px、等宽字体、浅灰底，禁止可拖拽 resize 手柄。

### 1.3 页面骨架与导航

- 顶栏 54px 单行：logo / 一级导航 / + 新建（primary small）/ 铃铛（红点徽标，不再
  以 "Needs attention" 文字占位）/ 头像。
- 详情页**没有页面标题**：对象头 = tertiary 返回（`← 返回技能`，全站一种模式）+
  名称 + 状态 pills + 右侧唯一主操作，随后 tabs。消灭"页面标题 + 卡片对象头"双标题。
- 内容宽度三档：创建/表单 720–900px 居中；列表/库 1200px；看板 fluid。
- 面包屑只在创建流使用；返回、取消不另设按钮位。

### 1.4 状态语言

- 空态统一 `EmptyState`：40px 图标容器 + 一句标题 + 一行说明 + 最多一个动作。
  列表为空给引导（入口小卡），不给只有表头的表格。
- Banner：顶部 sticky、可关闭、成功类 5s 自动消退；瞬时反馈（已保存等）走 toast，
  不常驻页面（删除常驻 "All changes saved" chip）。
- 状态 pill：统一 11px/600 圆角胶囊；草稿 grey、可运行 green、已共享 purple、
  需要注意 amber（缺材料/待确认）、风险 blue、冲突 red。色彩之外恒有文字。

### 1.5 深色 token 校准

深色不是简单反色。验收阈值：ghost/tertiary 文字对比度 ≥4.5:1；边框与禁用底 ≥3:1；
pill 用 tinted 底 + 亮文字 + 描边（见帧 19 深色对照带）。原 "Hide details" 不可见、
禁用按钮洗白等问题按此修复。

## 2. P1 · 核心流页面规格（帧 01–12）

### 2.1 Agent 页：多 session 版面（帧 01/02，参考 Codex 类 agent web GUI）

Agent 页本质是**多任务、多 Loop 并发**的管理台，单页时间线不够用。改为：

- **左栏 session 列表（236–246px，可折叠）**：顶部"任务 + ＋新任务 + ‹ 折叠"；
  折叠后收成 44px 图标条（» 展开 + 状态点仍可见）。列表按时间分组（今天/昨天/更早）；
  每行 = 状态点（进行中蓝色脉冲 / 排队灰 / 待确认 amber / 完成绿）+ 标题摘要 +
  状态/时间一行；**Loop 运行也是一种任务**，以 ⤴ 标记 + Loop 名（从看板"去 Agent 页
  运行 →"跳入时直达对应任务）。选中行高亮，点击切换主区。
- **主区**：选中任务的对话流（用户气泡右置、Agent 左置）+ composer 固定底部
  （提交即开新任务）。
- **空态（帧 01）**：左栏显示"还没有任务"引导，主区为标题 + 建议卡（3 张，点击填入
  composer）+ composer；不再有整屏虚空。

### 2.2 运行、上下文与结果：信息架构闭环（帧 02）

v1 的"上下文 / 运行详情 / 产物"三 tab drawer 被取消，因为它把三种该各就其位的信息
塞进了一个抽象容器。替代设计：

- **上下文内联**：任务用到的参考在"使用现场"可见——执行步骤直接写"读取 6 份访谈
  记录"，结果卡带"来源：访谈 ×6" chip。用户问"Agent 看到了什么"时，答案就在对话里，
  不需要一个标签页。
- **运行详情降级为两层**：进行中 → 时间线内联（"正在处理 第 N 步，共 M 步" +
  "执行细节 ▾"可展开步骤日志 + 显式取消）；完成后 → 模型/来源/用时/用量收进结果
  阅读页底部的"运行信息"折叠区（溯源信息，按需展开，不占常驻版面）。
- **产物不设列表 tab**：产物就在结果卡的 chips 里。**"打开结果"的闭环 = 结果阅读页**：
  右侧 384px 面板（桌面）/ 推进式整页（移动端），渲染好的 Markdown 阅读视图 +
  下载 .md / 复制内容 + 多产物头部 1/N 翻页 + 底部"运行信息"折叠区。
- 阅读页按需出现（点"打开结果"或产物 chip），✕ 关闭；不出现时不占版面——保持
  "细节默认收起，渐进披露"的原意，但每个面板都有具体职责。
- Loop 运行在本页生成 ⤴ 任务，统一执行、统一输出、统一历史；失败不自动切换模型、
  不伪装成功（不变）。

### 2.3 模型选择（帧 03）——无模式切换，输入时检测

- **取消"文本/图像"模式切换**：用户不该先声明模式。composer 工具条只有一个模型按钮
  （模型 chip + 附件 + ⌘⏎ + 发送）。
- popover 列出团队开通的全部受治理模型，**能力直接标注**（支持图片 / 仅文本），底部
  治理说明（"这里只选要用的模型，账号密钥由团队统一管理"）；键盘操作不变。
- **输入时检测**：拖入/粘贴图片而当前模型不支持时，图片以附件 chip 出现在 composer，
  notice 给出两个出路（"换模型 ▾" / "移除图片"），发送保持禁用并附 tooltip
  （"这个模型看不懂图片"）。不在输入前拦截，也不静默丢弃。
- 无可用模型：composer 上方独立 notice（原因 + "怎么开通"），发送禁用附 tooltip。

### 2.4 Loop 三态看板（帧 09）——运行回到 Agent 页

- 页面动作：primary"＋ 新建 Loop" + secondary"⇪ 上传 Loop"。技能类创建入口从本页
  移除，统一走顶栏 + 新建。同屏创建入口 ≤3。
- **看板只表达生命周期（设计中/可运行/已共享），不内嵌运行**：卡片快捷操作只留
  编辑/⋯；可运行卡的运行入口是跳转链接"▶ 去 Agent 页运行 →"，在帧 02 的任务栏生成
  一条 ⤴ 任务；运行结束后状态自动回写看板。历史运行从 Agent 页回看
  （已共享卡"最近一次运行 · 在 Agent 页查看 ↗"）。
- **修复 drop zone 语义**：空列只放统一 EmptyLane；拖拽时只有**目标列**高亮 drop
  target；源列不出现误导文案。
- Loop 卡：名称、状态 pill、元信息（节点/技能数、相对时间）、hover 快捷操作。
- AI 命令条升级为 hero 条：✦ + 占位文案 + ⌘K，聚焦环。
- 时间一律相对化，删除页脚时区说明。

### 2.5 Loop 创建入口与"第二跳"（帧 07/17/18）

- 入口页（帧 07）：720px 居中；两张入口卡 + "其他起点"内联行；**删除通栏取消灰条**。
- 每个起点都有明确落地页，不再是死路：
  - **空白 Loop** → 直接进 builder 大纲（builder 复用现有关键帧 03/04，不重设计）；
  - **从起点开始** → 帧 17 起点模板库：领域 chips 筛选 + 模板卡网格（用途、包含
    内容、发布组、版本），"用这个起点"复制草稿进 builder；
  - **复制现有 Loop** → 帧 18 选择对话框：搜索 + 行选择，页脚注明"复制为新草稿，
    原 Loop 不变"，确认"复制并打开"进 builder；
  - **从文档生成 / 导入定义** → 帧 08 提案检查（不变）。

### 2.6 Staged Proposal Review（帧 08）

- 顶部常驻 info banner："Loop 还没有创建"，确认后才保存，刷新从服务器恢复。
- 定义字段与节点标题行内可编辑；右侧摘要卡：状态 ✓ 列表 + 唯一 primary"保存为草稿"
  + tertiary"放弃提案"。commit pending 禁重复提交（不变）。

### 2.7 Skills 库（帧 10）

- 全宽表格改**行结构列表** + 360px 预览面板；每行直接露出"input → result"输入输出
  chips，不点进去就知道它干什么。
- 预览面板：对象摘要 + 按状态变化的唯一主按钮（缺材料→继续完善）+ tertiary"查看技能"
  + 图标定义行（要你提供/会生成/适合）+ 用在哪。
- 原生 select 换 segmented；搜索框 ⌘K；0 行时引导空态。

### 2.8 Skill 详情（帧 11）——自定义命名

- 按 1.3 去双标题；"继续编辑"全页一次。
- **自定义命名**：对象头名称可 ✎ 行内重命名（团队内唯一）；包名/ID 与版本规则不变；
  列表、预览面板、工作流引用处一律显示自定义名。
- 概览：**"它需要你提供"分两组**——需要的材料（要分析的文件/文本，必须/可选）与
  需要的参数（入参，必须/可选）；两组都可以没有，都没有时显示"不需要，直接就能跑"。
  会生成以人话命名（决策摘要 Markdown · 一定会生成）；它能做什么（权限）图标定义行；
  用在哪空态给去向。

### 2.9 试运行与发布（帧 12，单页最大改造）

- 显性三步：① 先试跑一次 → ② 确认它的能力范围 → ③ 发布固定版本。
- 完成步折叠为绿色 ✓ 摘要（可展开重跑）；当前步展开；后续步锁定并注明解锁条件。
- 步骤 1 表单按 1.2 规格；主按钮卡内右对齐；结果以结果面板呈现。
- 步骤 2：能力范围摘要 notice + checkbox"我明白它能做什么、不能做什么" +
  primary"确认，继续"。步骤 3：版本号 + 变更说明 + 受影响工作流列表。

### 2.10 创建向导（帧 04/05/05B–05F/06）

- 从 600px modal 解放为专注 route（桌面 max 900px）；**左侧步骤导航**（落实组件规格），
  显示"第 N 步，共 7 步"，已完成可回跳，返回不丢数据。
- 各步内容：

| 步骤 | 帧 | 内容 |
|---|---|---|
| 1 类型 | 05 | 2×2 卡片：提示词 / 脚本（Python 或 TypeScript）/ 工具（→帧 18）/ 工作流（→帧 07） |
| 2 做什么 | 05B | 职责一句话 + **需要的材料**（文件/文本 + 必须/可选）与**需要的参数**（入参 + 必须/可选）两组行编辑器，都可为空（空 = "不需要，直接就能跑"）+ 会生成（人话命名 + 一定会生成），与详情页展示一一对应 |
| 3 怎么运行 | 05C | **运行环境可选**：Python 3.12 / Node.js 20 · TypeScript（均在隔离沙箱）+ 超时/内存 stepper + 沙箱边界说明；环境目录由后端下发、前端不硬编码，新环境找管理员开通（前后端联调：选择只保存 runtime id） |
| 4 分类 | 05D | 领域 chips（与资源库领域 rail 同一套）+ 适合场景 tags。**风险不由用户自评**——由系统按能力边界推导展示 |
| 5 草稿内容 | 05E | 将生成的文件清单（SKILL.md / skill.runtime.json / scripts/main.py，作用 + 大小 + 预览）；明示创建后仍可改 |
| 6 试运行 | 05F | 只收集"要证明什么 + 示例输入 + 预期（可选）"，不在向导里真跑；保存后自动带入帧 12 |
| 7 最后检查 | 06 | 概述（名称 + 职责/作用 + 领域与场景）/ 定义（类型 + 运行环境）/ 输入输出 / 包含文件 / 试运行要证明，分区展示 + 每区"返回修改"；footer 治理承诺；主按钮"没问题，保存草稿" |

- footer 恒为：左 tertiary"← 上一步"（第 1 步为"取消"），右 primary"继续 →"；下一步只在
  当前字段校验通过后可用（不变）。

## 3. P2 · 打磨（帧 13–19）

### 3.1 Team Library（帧 13）——资产平台化，领域分类

按"Skill OS / Loop OS 的团队资产平台"重排三栏：

- **左：领域 rail（196px）**：全部资产 + 领域分组（产品/研究/数据/工程，各带计数）；
  状态过滤（已安装/有更新）收进同栏；脚注注明**本版不含权限设置**——团队内均可安装，
  可见性以标签区分（团队 / 仅本组）。
- **中：类型 tabs（技能/工作流/起点模板，带计数）+ 搜索 + 行列表**。每行直接露出：
  用途一句话 + 输入输出 chips（input → result / N 节点 · M 技能）+ 领域标签 +
  被几个工作流用 + 安装状态 + 唯一动作。**不点进去就知道这个资产干什么、属于哪个
  领域。**
- **右：预览面板**：能做什么（一段话）+ 包含什么 + 用在哪 + 版本对比（你用 v4.1 ·
  最新 v4.3）+ 治理 notice + 唯一主按钮（安装 / 看看影响再决定）。
- 空态按 1.4 统一组件。

### 3.2 Inbox（需要处理）

  route），按对象列待处理项、每项一个动作；0 项时不占位。

### 3.3 移动端（帧 14/15/16）——四页齐全

  composer 在底部）；"打开结果"推进到整页结果阅读页（渲染预览 + 下载/复制 +
  运行信息折叠区）。

## 8. 文案规范（说人话）

界面文案面向结果、动词自然；工程词不进界面，治理语义用结果语言表达。

| 不用（工程化） | 用（人话） |
|---|---|
| 检查并创建草稿 / 检查并创建私有 Draft | 没问题，保存草稿 / 保存为草稿 |
| Schema 校验通过 | 格式检查通过 |
| 尚未编译 · 保存后进入设计态 | 保存后随时可以接着改 |
| staged proposal | AI 提案（可以直接改） |
| 冒烟测试 / 冒烟目的 | 试运行 / 试运行要证明什么 |
| 运行安全示例 | 先试跑一次 |
| 确认权限 | 确认它的能力范围 |
| 职责与输入输出 | 它做什么 / 要你提供 / 会生成 |
| 需要 / 生成（裸标签） | 要你提供 / 会生成 |
| 必定生成 | 一定会生成 |
| 需要资料 (Needs material) | 缺材料 |
| 被用于 | 用在哪 |
| FIFO / 排队位置 | 排队第 1 位 / 轮到会自动开始 |
| 已固定 revision | 本次运行锁定不变 |
| 仅可查看 | 只能看，不能改 |
| 版本冲突 | 和别人改重了 |
| 无法加载此对象 | 这个页面暂时打不开 |
| 更新影响 | 这次更新会影响谁 |
| Provider 协议和密钥由后端持有 | 账号密钥由团队统一管理 |
| 无可用模型配置 | 还没有可用的模型 / 联系管理员开通 |
| input schema / 裸"input 必填" | 需要的材料（文件，必须/可选）+ 需要的参数（必须/可选）；都没有就显示"不需要，直接就能跑" |
| 文本/图像模式切换 | 取消；能力由模型表达，输入时检测提示 |
| Artifacts（产物 tab） | 结果卡 chips + 打开结果 → 阅读页 |
| Context / Run details（drawer tab） | 上下文内联 / 执行细节内联 + 运行信息折叠区 |

规则：
- 按钮文案 = 用户的下一步（"保存草稿""看看影响再决定"），不是系统动作（"提交""执行"）；
- 一句说明只讲一件事；每个错误 = 一个原因 + 一个恢复动作；
- 文件名、版本号、包名等技术标识保留原文，不强行翻译（SKILL.md、.loop.json、v1.3）。
