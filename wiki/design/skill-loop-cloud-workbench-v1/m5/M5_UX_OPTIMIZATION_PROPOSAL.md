> drawer 等产品语义也已被已批准的 M5 v2 总览覆盖。

- 日期：2026-07-28
- 状态：**提案，未批准**。批准后再决定如何合入 `README.md` / `COMPONENT_INTERACTIONS.md`

## 0. 总体判断

现行设计的功能骨架是对的：单一 composer 主轴、drawer 渐进披露、三态看板、
staged proposal 边界、Test/Validate/Publish 独立动作、能力过滤模型切换——这些**保留**。

问题出在执行层：页面骨架、按钮层级、表单控件、空态、动线收尾这五件事没有设计，
导致每个页面都退化成"标签 + 裸输入框 + 一排等权按钮"的填表页。本方案不引入第二套
视觉系统（沿用方案 A 的 token 与灰色中性底 + 单一蓝色强调），只把缺的交互设计补上。

另注：本次 capture 有 31 帧失败（proposal review、builder canvas、run 各态、model
switch、state board 等），这些帧只能依据文字规格推断，方案中对它们的覆盖以系统性
改动的方式给出；实施前应先恢复 capture。

## 1. 诊断：六个系统性问题

### 1.1 双标题与骨架冗余
几乎每个页面都是"页面大标题 + 卡片内对象头"重复一遍同样的信息：
`技能概览`（页面标题）下再出现一个含 `← 返回技能 / 工作区技能 / decision-follow-up-writer`
的大卡片（`skill-detail`、`skill-versions` 同病）。面包屑、返回按钮、页标题三种
导航并存，首屏 200px 被导航消耗，内容被压到折叠线以下。

### 1.2 动作没有层级，且大量重复
- Loops 页并排 4 个**等权黑色实心按钮**（Create Loop / Upload Loop / Create skill /
  Upload skill），又与顶栏 `+ Create` 全局菜单的 4 项完全重复——同一屏 9 个创建入口。
- `skill-versions` 一页里"继续编辑"出现两次。
- Loop 创建入口页底部一个**通栏"取消"灰条**，是全页视觉重量最大的元素——层级彻底
  倒挂：取消成了主角。
- "Back to Skills" 在一处是黑色实心按钮，在另一处是纯文字链接，返回模式不统一。

### 1.3 表单控件裸奔 + 原生控件混用
- `skill-validation-test`（测试与发布）是最严重的填表页：`Test name`、
  `What should this test prove?` 只有标签没有可见输入框（无边框无底色），两个巨大
  的空 JSON textarea 带 resize 手柄，再接一个通栏蓝色巨按钮。
- 原生 `<select>`（Skills 库的 All 筛选）、原生 number spinner、原生
  `Choose Files` 与自定义组件混排——移动端导入页甚至**原生文件按钮和自定义
  dropzone 上下叠放，两个文件选择器并存**。
- 视觉语言因此断裂：同一页里出现 3 种控件风格。

### 1.4 空态是虚空，不是引导
- Loop 看板三列全空时，每列空态样式各不相同：Drafts 列是一个文案误导的虚线框
  （见 1.5），Ready 列是图标+两行字，Shared 列是图标+字+按钮。没有统一的
  EmptyLane 语言。
- Agent 首页空态：标题悬浮在整屏中央虚空，两个示例 prompt 是光秃秃的 pill，
  与沉底的 composer 相距 400px+，视线动线断裂。
- Team Library 空态只有一块白板+一个按钮。

### 1.5 看板 drop zone 语义错误
Drafts 列内的虚线框写着"Drop here to move to **Ready**"，Ready 列底部的虚线框写着
"Drop here to move to **Shared**"——drop 提示出现在**源列**而不是目标列，且空列里
根本没有可拖的对象。正确做法：空列只放"对象如何到达这里"的说明；拖拽进行中时，
目标列才高亮出 drop zone。

### 1.6 移动端堆叠过载 + 深色 token 对比度失守
- 移动端 Loops 页一屏内塞了：需要处理面板、AI 命令条、4 个创建按钮、看板列——
  信息过载；顶栏 `+ 铃铛 Needs attention 头像` 挤占一行，下方再一行导航 tab，
  "Team libr…"被截断。
- 深色主题下 `m5-agent-details-drawer` 的 "Hide details" 按钮几乎不可见；
  禁用按钮、徽章在深色下对比度未达标。深色 token 只做了反色，没做对比度校准。

## 2. 优化方案

### 2.1 页面骨架与排版（全局，P0）

- 取消"页面标题 + 对象头卡片"双标题。列表/看板页保留页面标题（24px + 一行副标题）；
  详情页**没有页面标题**，直接是对象头：返回链接（统一纯文字 `← 返回`，全站一种
  模式）+ 名称 + 状态 pills + 唯一主操作，随后紧跟 tabs。
- 内容宽度分三档：表单/创建流 720px 居中，列表/库 1200px，看板 fluid。消灭
  "卡片套卡片"：详情页各分区用标题 + 分隔线，不再包一层灰底大卡。
- 建立间距节奏：页面 padding 24/32，section 间距 32，区标题 16px 半粗 + 4px 说明。
- 每屏**只有一个 primary 按钮**；返回、取消一律 tertiary（文字级）。

### 2.2 按钮与控件体系（全局，P0）

- 三级按钮定死：primary（蓝实心，每屏一个）/ secondary（描边）/ tertiary（文字）。
  **黑色实心按钮从体系移除**（现 4 个黑按钮、Back to Skills 黑按钮均改级）。
- 禁用态必须附带原因：tooltip 或按钮下方一行 inline hint，二选一，全站统一。
- 替换所有原生控件：`select`→自定义 dropdown，`number`→自定义 stepper，
  `file`→统一 dropzone（点击或拖拽，**全站只有一个文件选择入口**）。
- 输入控件统一规格：可见边框（中性灰）、8px 圆角、focus 蓝环、标签在上、
  帮助/错误文本在下 4px。不允许"裸标签无框"。

### 2.3 空态与状态语言（全局，P0）

- 统一 `EmptyState` 组件：40px 图标容器 + 一句话标题 + 一行说明 + 最多一个动作；
  列表空态给引导（两张入口小卡），不给"只有表头的表格"。
- 统一 `Banner`（连接恢复等）：顶部 sticky、可关闭、成功类 5s 自动消退。
- 状态 pill（Draft/Ready/Shared、风险、版本）同一套尺寸与配色，深色主题单独校准
  对比度（禁用态、徽章、"Hide details" 这类 ghost 按钮为验收点）。

### 2.4 Agent 首页（P1）

- 空态重构为一个垂直组，放在内容列上 1/3 处，**紧贴 composer**：一行工作导向标题
  + 最多 3 条建议 prompt（带图标和类别标签的卡片行，点击即填入 composer，不是
  装饰 pill）+ 有数据时下方接"最近工作"紧凑列表（最多 3 条，行结构）。中央虚空消除。
- 模型不可用：错误不再塞进 composer 内部角落的红字，改为 composer 上方一条
  inline notice（图标 + 原因 + "去配置"链接按钮），Send 保持禁用并给 tooltip。
- Text/Image 切换改为带图标的 segmented control，与模型 chip 同处 composer 工具条；
  图像入口同时提供 paperclip 图标。
- Details 按钮加快捷键标注；drawer 打开时主列**压缩让位**而不是被遮挡。

### 2.5 Loop 生命周期看板（P1）

- 动作收敛：页面级只保留"新建 Loop"（primary）与"上传 Loop"（secondary）；
  技能类入口从本页移除，统一走顶栏 `+ Create`。同屏创建入口从 9 个降到 3 个以内。
- 修复 drop zone 语义：空列用统一 `EmptyLane`（图标 + "如何到达这里"说明 + 适用时
  一个动作）；拖拽进行中目标列才出现高亮 drop zone；源列不再出现误导文案。
- AI 命令条升级为看板 hero 条：大圆角、浅色底、✦ 图标 + ⌘K，视觉上明确区别于普通
  输入框，表明"这是提案入口"。
- Loop 卡片（有数据时）：名称 + 状态 pill + 节点/引用技能计数 + 上次运行结果图标 +
  相对时间，hover 浮出 Run / 编辑 / ⋯。
- 移除页脚 "All times shown in your local time"（时间一律相对化，tooltip 给绝对值）。

### 2.6 Loop 创建入口（P1）

- **删除通栏"取消"灰条**；取消改为右上角 tertiary 或直接走面包屑返回。
- 两张入口卡收敛到 ~120px 高：左侧 48px 图标容器 + 标题 + 两行说明 + 底部一行预期
  说明 chip（如"先检查 AI 提案，不产生正式 Loop"）；hover 边框加深 + 微阴影；
  支持方向键 + Enter 选择。
- "其他起点"展开为内联行，不跳转。
- 整页 720px 居中，垂直节奏 24/16/32，消除底部 300px 空白。

### 2.7 Skills 库（P1）

- 放弃全宽表格（6 列表头只装 1 行数据且徽章被截断）。改为行结构列表：图标 +
  名称 + 用途一行摘要 + 右侧状态 pill 与动作；选中行右侧出 360–400px 预览面板。
- 预览面板：对象摘要（名称/状态/风险/版本）+ 按状态变化的唯一主按钮
  （Needs material → "继续准备"）+ 次级"查看技能"；"How this skill works" 从裸
  键值对改为带图标的定义列表。
- 原生 `All` select 换 segmented/dropdown；搜索框接 ⌘K。
- 0 行时显示引导空态（创建 / 上传两张小卡）。

### 2.8 Skill 详情（P1）

- 按 2.1 去双标题；"继续编辑"全页只出现一次，放对象头作为主按钮。
- 概览 tab：`需要/生成` 用两列 chip（`input·必填` / `result·必定生成`）；
  `权限与设置` 用图标行（外部动作/连接/安全说明各一图标 + 一句话）；
  每区右上角"编辑"跳对应 tab。

### 2.9 测试与发布（P1，单页最大改造）

把"测试 → 确认 → 发布"从一页长表单改为**显性步进流程**：

- 页顶步骤条：1 运行安全示例 → 2 确认权限 → 3 发布固定版本。
- 每步一张区块卡：未完成步骤折叠锁定；当前步骤展开；已完成步骤收起为一行绿色
  勾选摘要（可展开重跑）。
- 步骤 1：表单控件全部按 2.2 规格带框；JSON 区固定 ~160px 高、等宽字体；
  "运行技能测试"为卡内右对齐 primary（不再通栏）；结果（通过/失败/日志）在按钮
  下方出结果面板。
- 步骤 2：checkbox + 权限摘要，"确认此技能"在步骤 1 通过前锁定并给原因。
- 步骤 3：版本号 + 变更说明 + 受影响工作流列表；发布按钮在步骤 2 完成前锁定，
  原因走 tooltip。

### 2.10 创建向导（P1）

组件规格写的是"Desktop 左侧步骤导航"，实现却塞成了 modal 顶部 7 个小圆点——按规格
改回来，并顺手解决 modal 压迫感：

- 桌面：7 步向导从 600px modal 解放为**专注 route（或 ≥960px 宽 dialog）**，
  左侧步骤导航（当前步骤高亮、已完成可回跳、显示"第 N 步 / 共 7 步"）。
- 类型选择：4 类型 2×2 卡片（图标 + 一句话）；Tool/Workflow 卡片明示去向箭头。
- 导入：4 来源 segmented + **只保留一个 dropzone**；删除原生 `Choose Files` 按钮。
- Review：分区摘要 + 每区"返回修改"链接；主按钮"检查并创建草稿"。
- 移动端：向导改全屏 route，顶部细进度条 + 当前步骤名，底部 sticky footer
  （上一步 / 下一步）。

### 2.11 Team Library / Inbox（P2）

- Library 空态按 2.3 统一组件，居中 + 引导动作；过滤 chips 加计数。
- 有数据时行结构：图标 + 名称 + owner + 版本 + 可见性 + 安装状态 + 唯一动作。
- Inbox（需要处理）：不再作为常驻面板塞进 Loops 页。改为顶栏铃铛 + 红点计数，
  点开为 popover/独立 route，按对象列待处理项、每项一个动作；0 项时不占位。

### 2.12 移动端（P2）

- 顶栏合并为一行（logo / + / 铃铛徽标 / 头像）；主导航改**底部 tab bar**
  （Agent / 技能 / 工作流 / 资源库，图标 + 短标签），解决 "Team libr…" 截断并释放
  首屏 ~88px。
- "所有更改已保存"等状态 chip 不常驻，改为保存时短暂 toast。
- 看板在移动端为单列竖排 lanes（现状正确），但移除页内 inbox 面板与重复创建按钮
  （走底部 tab 中央或顶栏 +）。

### 2.13 主流程动线（验收视角）

- 创建 Loop：看板 → 入口选择 → 提案检查 → 草稿（builder）→ 验证 → Ready。
  每屏一个主按钮；返回不丢状态；提案页顶部常驻"尚未创建 Loop"。
- 创建技能：库 → 类型 → 左侧步骤导航向导 → 草稿详情 → 步进式 测试/确认/发布。
- Agent：首页 → composer → Running/Queued 可见 → 结果流 → drawer 按需。
- 团队库：浏览 → detail → 安装/更新 → 回到看板可见。

以上动线不变产品语义，只是把断掉的视觉引导（每屏主按钮、进度可见、返回可逆）
补齐。

## 3. 不变项（明确边界）

- 产品语义与对象边界：三态 lifecycle、staged proposal、Draft 边界、Test/Validate/
  Publish 独立、modelProfileId-only、能力过滤——全部不动。
- 路由、数据所有权、bundle 拆分、`fflate`/Flowgram 延迟加载——不动。
- 视觉母版：灰色中性底 + 单一蓝色强调 + light-first + 行结构优先——不动；本方案
  只补层级、控件、空态与动线。
- 12 个人工关键帧清单与 hash-bound review 机制不变；优化实现后按同一清单重拍。

## 4. 实施优先级与验收

|---|---|---|
