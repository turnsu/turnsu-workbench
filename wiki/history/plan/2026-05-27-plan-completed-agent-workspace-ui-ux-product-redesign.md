# Agent 工作台 UI/UX 产品重构计划

Date: 2026-05-27

## 结论

当前版本已经具备工程 MVP 能力，但还不是一个自然可用的 Agent 产品。

直接判断：

- 它能展示 agent runtime、情报对象、运行记录和安全边界。
- 它还不能让普通用户在 30 秒内明确知道“今天该处理什么、Agent 正在帮我做什么、我下一步该点哪里”。
- 当前 UI 的问题不是缺功能，而是产品主线、信息层级和用户语言还没有完全收敛。

最尖锐的问题是：界面仍然像把 Agent 系统结构摊给用户看的控制台，而不是一个以用户目标为中心的工作空间。

## 核心问题

### 1. 主任务不突出

用户打开后第一眼不清楚主动作是什么：

- 看情报？
- 问 Agent？
- 查 Token？
- 看运行状态？
- 做安全复核？

这些入口同时出现，导致注意力被分散。

### 2. 仍然有 runtime-first 的产品结构

可见文案已经从 `Crystal / Inspector / Artifact / Policy` 等底层词改成了中文用户层表达，但界面组织仍然偏底层。

用户真正需要的是：

- 今天有什么重要信号？
- 为什么重要？
- 我能不能信？
- 我现在要不要行动？

而不是优先理解 run、record、module、bridge、health 等系统结构。

### 3. Agent 工作台还只是“功能并列”

当前 Agent 工作台已经有：

- 对话
- 能力选择
- 图片附件
- 任务列表
- 详情面板
- 运行进度

但它们只是被摆在一个页面里，还没有形成清晰动线：

```text
输入目标 -> Agent 理解任务 -> 选择能力 -> 执行 -> 展示依据 -> 等待确认 -> 形成结果
```

### 4. 情报卡还不像决策卡

情报卡现在更像系统生成的一条对象记录。

它应该直接回答：

- 发生了什么？
- 为什么重要？
- 依据是什么？
- 风险是什么？
- 我现在该做什么？

### 5. 视觉语言偏终端，不够 macOS 专业工作软件

当前视觉有明显的工程控制台气质：

- 深色密集卡片过多
- monospace 使用过多
- 状态标签太多
- 运行细节过早暴露
- 技术路径和记录文件容易抢主内容注意力

后续应该向更克制的 macOS 专业工具体验收敛：更少噪音、更清晰层级、更少系统词、更少常驻技术细节。

## 产品三层结构

后续产品应明确分为三层。

### 第一层：今天要处理什么

用户层默认入口。

应展示：

- 今日重点情报
- 风险预警
- 待确认行动
- 推荐下一步
- 数据是否可靠

### 第二层：Agent 正在帮我做什么

Agent 工作台主线。

应展示：

- 当前任务
- Agent 回复
- 能力调用
- 等待确认
- 结果产出
- 后台任务进度

### 第三层：为什么可信

解释层和审计层。

应展示：

- 微信依据
- 链上/行情依据
- 数据新鲜度
- 安全边界
- 运行记录
- 记录文件

当前版本的问题是三层混在一起了。

## 推荐信息架构

左侧导航收敛为 4 个一级入口。

### 1. 今日情报

默认首页。

只回答一个问题：今天我应该关注什么？

不默认展示运行日志、记录文件、module pipeline 或过多底层状态。

### 2. Agent 工作台

用户输入任务、上传图片、选择能力、查看 Agent 执行和确认行动。

这是主动操作空间。

### 3. 观察对象

把 Token、群组、地址、人物、项目、watchlist 统一放在这里。

当前 `微信收件箱`、`Token 详情`、`观察列表` 不应长期作为同级主导航同时暴露。

### 4. 数据与安全

给高级用户和开发 review 使用。

包含：

- 数据源状态
- 后台服务状态
- 运行记录
- 安全边界
- 日志
- 记录文件

## Agent 工作台改版方案

当前四区布局方向可保留，但需要重新排序和降噪。

### 左侧：任务与上下文

展示：

- 当前任务
- 历史任务
- 已选择上下文
- 已添加图片
- 已选择群组 / Token / 情报卡
- 能力开关

不要把 raw tool list 当成主内容。

能力以用户语言展示：

- 微信情报
- Token 识别
- 行情快照
- 链上检查
- 图片理解
- 生成交接包
- 申请电脑操作

### 中央：Agent 对话区

这是主舞台。

要求：

- Chat 占最大面积。
- Composer 固定在底部。
- 输入框提示改成用户任务语言。
- 主按钮从“交给 Agent”进一步明确为“开始分析”。
- Agent 回复中直接展示结论、依据、下一步，而不是流式日志优先。

建议输入提示：

```text
告诉 Agent 你要盯什么、分析什么、生成什么
```

### 右侧：依据与确认

默认文案：

```text
选择一条情报、建议或消息后，这里会显示判断依据、关联数据和可执行动作。
```

选中情报后展示：

- 结论
- 可信度
- 数据状态
- 微信依据
- 链上/行情依据
- Agent 为什么这样判断
- 可执行动作
- 安全说明

高级信息如执行记录、路径、runID、policy detail，全部折叠到“技术详情”。

### 底部：运行进度

默认折叠。

只有在以下场景突出：

- 任务运行中
- 任务失败
- 等待确认
- 长任务后台执行

运行进度不应该长期占据主页面注意力。

## 情报卡改版方案

情报卡应从数据对象改为决策对象。

每张卡统一为 5 个区域。

### 1. 一句话结论

示例：

```text
BTC 讨论升温，但行情数据过期，需要先验证。
```

### 2. 为什么重要

示例：

```text
多个微信群同时出现 BTC 相关讨论，且关联到市场/链上监控对象。
```

### 3. 风险与可信度

不要只展示 `0.57`。

应展示：

```text
可信度：中 · 数据部分过期
```

数字可以保留在次级位置。

### 4. 依据

示例：

```text
3 条微信群消息 · 1 个行情快照 · 0 个链上快照
```

### 5. 建议动作

每张情报卡只保留一个主动作，其他动作进入更多菜单。

建议动作：

- 加入观察列表
- 创建跟进任务
- 生成交接包
- 忽略

## 文案规范

### 禁止优先暴露的词

以下词可以保留在技术详情中，但不应作为普通用户主界面标题：

- Crystal
- Inspector
- Artifact
- Run Deck
- Run ID
- Daemon
- Provider
- Policy
- Tool Call
- Session
- Manifest
- Pipeline

### 推荐用户层词汇

| 系统词 | 用户层表达 |
|---|---|
| Crystal | 情报卡 / 情报 |
| Inspector | 详情与依据 |
| Artifact | 记录文件 |
| Run Deck | 运行进度 |
| Run ID | 执行记录 |
| Daemon | 后台服务 |
| Provider | AI 模型 |
| Policy | 安全边界 |
| Tool Call | 能力调用 |
| Session | 任务对话 |
| Manifest | 记录清单 |
| Pipeline | 处理进度 |

## 视觉方向

后续视觉应从“黑客终端感”转为“macOS 专业工作台”。

原则：

- 减少全大写英文。
- 减少 monospace，只保留数字、路径、ID。
- 状态颜色只保留三类：
  - 绿色：可用 / 完成
  - 黄色：需确认 / 数据过期
  - 红色：阻断 / 失败
- 卡片减少边框和密度，增加留白。
- 每个页面只保留一个主动作。
- 技术细节默认折叠。
- 用户语言优先，系统语言隐藏。

## Phase 计划

### Phase 1：文案与信息架构收敛

目标：用户不需要理解 runtime 也能操作。

任务：

- 首页改为“今日情报”。
- Agent 页面作为默认主工作流之一。
- 首页隐藏旧 `Agent 运行概览`。
- 底部运行栏默认只在“数据与安全”显示。
- 所有 raw ID、路径、执行记录默认折叠。
- `数据与运维` 改为高级区。

验收：

- 用户不理解 runtime 也能知道首页在让他看什么。
- 首页不再同时展示过多系统运行结构。
- 技术信息仍可访问，但不抢主路径。

### Phase 2：Agent 工作台重构

目标：让 Agent 对话成为主入口。

任务：

- 中央 Chat 占最大面积。
- 左侧只保留任务、上下文、能力开关。
- 右侧只展示依据和确认。
- 运行进度折叠到底部。
- Composer 增加任务模板：
  - 分析今日重点
  - 检查某个 Token
  - 从图片生成分析
  - 生成交接包
  - 创建长期监控

验收：

- 用户打开 Agent 工作台后能立即输入任务。
- 用户能明确知道哪些能力被打开。
- 用户能看到 Agent 的结论和下一步，而不是先看到系统日志。

### Phase 3：情报卡重构

目标：从数据对象变成决策对象。

任务：

- 情报卡改为：结论、重要性、依据、风险、建议动作。
- 置信度改成中文等级 + 数字细节。
- 数据过期/降级要解释影响。
- 卡片上只保留一个主动作。

验收：

- 每张情报卡能独立回答“为什么我要看它”。
- 用户不用打开详情也能判断是否继续处理。
- 数据状态对决策影响清晰可见。

### Phase 4：确认与安全体验

目标：让用户放心交给 Agent。

任务：

- 所有外部动作进入确认面板。
- 真实微信、交易、发消息继续阻断。
- Computer Use 显示为“申请电脑操作”。
- 每个行动建议都显示：
  - 会做什么
  - 不会做什么
  - 是否需要用户确认
  - 会写入哪些本地记录

验收：

- 用户能清楚知道 Agent 的权限边界。
- 敏感动作不会被误认为已经执行。
- 接受建议只产生明确的本地副作用。

### Phase 5：人工 review 体验

目标：双击桌面 app 后 30 秒内能判断产品是否成立。

任务：

- 首屏有示例任务。
- 无数据时也能展示空状态动线。
- Agent 工作台能跑一条完整模拟任务。
- 每个结果都能点开依据。
- 每个建议都能接受/拒绝。
- 数据与安全页能看到真实运行状态。

验收：

- 用户不需要阅读 wiki，也能完成一次人工 walkthrough。
- review 路径稳定：打开 app -> 看今日情报 -> 进入 Agent 工作台 -> 发起任务 -> 查看依据 -> 接受/拒绝建议。
- 失败和降级状态可理解、可解释、可复盘。

## 总体验收标准

改完后，用户应该能在不理解底层词的情况下完成任务：

- 不知道 Crystal，也能看懂“情报卡”。
- 不知道 Inspector，也能找到“依据”。
- 不知道 Artifact，也能知道“记录文件”。
- 不知道 Daemon，也能知道“后台服务是否连接”。
- 不知道 Tool Call，也能知道“Agent 调用了什么能力”。
- 不知道 Policy，也能知道“哪些动作被允许，哪些被阻断”。

最终产品判断：

```text
当前版本是有能力的工程 MVP。
下一步不应该继续堆功能。
下一步应优先收敛主动线、情报卡、Agent 工作台和安全确认体验。
```
