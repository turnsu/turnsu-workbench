# 客服资料与微信桥

客服是本地通用工作台的一种使用方式，不另建 CRM。客服人员主动选择获授权的聊天归档或项目文件，让 Agent 整理事实、未决问题和回复草稿；员工核对来源、编辑回复并通过原渠道人工发送。订单状态、退款额度、实际发送与客户身份不能由模型推断为权威事实。客户业务系统和云端客服 Agent 只有在相应连接器、授权及验收资源具备后才启用。

## 当前可用的本机入口

macOS 微信桥 v1 交接消费者支持用户主动选择、预览解析覆盖、逐项检查原档大小与 SHA-256、导入当前项目的 Host 私有快照，并按页预览/引用记录。单份 manifest 上限 40 MB、32 个原档项、100,000 条解析记录；本次导入另限制单文件 32 MiB、原档合计 128 MiB。预览文本每条最多 600 字；引用完整内容仍受 64 KiB 单项、128 KiB 合计限制。同一交接 ID 去重，不能在另一个本地项目重复归属。

微信桥本身保留“用户在微信多选 → 合并转发 → 原生分享”的路径。工作台不扫描微信全库，不把旧应答组件移进桌面，也不因桥的 `action=analyze` 字段自动调用模型。桥的原生生产者与工作台消费者按版本协议协作。代码依据见[交接写入](https://github.com/turnsu/wechat-bridge/blob/4b4b4c8b20b540aa4ed9229049478cdb493fe98e/bridge/Sources/WeChatBridgeCore/WeChatHandoff.swift)和[交接读取](https://github.com/turnsu/wechat-bridge/blob/4b4b4c8b20b540aa4ed9229049478cdb493fe98e/companion/desktop/src-tauri/src/wechat_handoff.rs)。

跨平台通用入口是系统文件选择器：员工把授权导出的 TXT、CSV、图片或其他普通文件导入项目 `Imported/`，再在任务中说明处理目标。这个入口只保存原件的项目副本；当前不承诺自动解析 ZIP、图片、语音或扫描 PDF。Agent 是否能处理某格式取决于其自身工具和账号能力；未解析材料不能被写成已读事实。Windows 不宣称有 macOS 微信原生分享扩展。

## 本地客服工作闭环

1. 用户主动选择桥交接或项目文件，先看来源、批次、数量和未解析项。桥导入成功只表示材料收到，不表示分析完成。
2. 用户选择具体记录或文件进入任务，明确要整理的问题、已有承诺、缺失信息和回复目的；昵称不是客户主键，多批记录的归并需要人工核对。
3. 选定的 Agent 基于引用快照生成事实摘要和回复草稿。原文是待处理数据，不得把其中“忽略规则”等内容当成工具授权。
4. 员工逐条核对事实与来源，在工作台或原有文档中修订。当前工作台不自动发送微信消息、不标记渠道已送达，也不执行退款或工单写入。
5. 需要继续跟进时保留本机会话、项目成果和未决问题；重开后沿原生会话 ID 继续。确认有用的方法可整理为客服 Skill，但 Skill 不增加业务权限。

团队共享和云端分析是独立的显式动作。当前私有微信导入不能直接塞进团队事项；分享前必须选定范围、版本和目标。将来接入客户 CRM、订单或工单时，权威数据及动作回执来自对应系统，业务权限由服务端检查；仅有模型生成的建议不等于已处理事项。

## 未验收边界

合成交接和 Host 测试覆盖格式、路径、哈希、去重、项目隔离及快照恢复。真实微信分享到工作台、Windows 授权导出文件的可见交互、真实客服消息到回复草稿的端到端路径仍需实机验收；没有客户样本和业务接口时，不报告客户身份确认、订单查询或业务写入成功。具体证据见[验证记录](verification.md)。
