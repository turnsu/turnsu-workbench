## 1. 交付目标与范围

企业员工安装工作台并加入公司工作空间后，即可处理本地文件或获授权的客户记录；需要云端服务时提交可核对的任务与资料，收到结果后完成审核、回复准备或业务写入，并能在故障后继续。公司用同一发行包服务客户，针对性适配发生在插件、Skill、企业配置和云端业务系统中。

完整版本必须交付以下六项，不将后三项推成无期限的“以后优化”：

1. 企业接入与多 Agent 执行：邀请登录、企业配置、客户偏好的 Agent 接入与默认选择、可恢复的运行依赖安装、模型连接与费用归属；Pi、Claude Code、Codex 都是正式入口。
2. 本地工作：选定目录、常用文档与表格、受控网页资料获取、结果预览导出；文件修改保留差异或可恢复副本。
3. 客服工作：微信桥 / 文件导入、来源预览、客户事项、业务查询、云端分析、人工审核、回复及处理结果记录。
4. 持续任务：本地与云端同一事项、可靠交接、补充资料、负责人、截止时间、活动记录、必要通知和可编辑记忆。
5. 客户适配：受控连接器与插件、固定版本 Skill / Loop、企业能力包、试跑、发布和回退；复用现有模块。
6. 企业交付：macOS / Windows 实机、签名发行、升级和恢复、资源上限、诊断支持以及两个不同客户的日常使用验收。

不新增全量聊天采集、独立 CRM、通用工作流编排平台、面向所有软件的自动点击引擎，也不承诺支持所有文档格式和所有客户系统。首版明确支持的路径必须完整；超出能力时保留原资料、解释限制并提供人工接续。

### 1.1 多 Agent 执行与客户偏好：首版必交付

工作台对接客户实际使用的执行 Agent。企业可选择自己的默认执行器，员工可在允许范围内沿用个人偏好，不要求统一改用 Pi。**Agent、模型、账号来源和执行位置分别配置与展示**：更换模型网关不等于接入另一种 Agent；本地 Agent 也不等于本地模型。

| 接入范围 | 本轮交付要求 |
| --- | --- |
| Pi、Claude Code、Codex | 在现有接入上完成统一发现、版本 / 登录状态、运行、流式事件、批准、停止和恢复；分别验证，不能以一种通过替代另两种 |
| 客户已有安装与账号 | 明确绑定用户选择的安装及原生账号；按用户操作登录，不复制私人凭据、覆盖全局配置或强制重装；已有历史按声明能力选择性关联 |
| 企业提供的执行环境 | 为没有既有环境的员工配置企业选定且已通过验证的 Agent；受管是具体运行配置及控制能力，不是 Pi 的专属名称 |
| 新增执行器 | 通过适配器注册、能力描述和受控依赖接入；本轮以 OpenCode 作为第四个真实扩展验收对象，客户明确指定其他 Agent 时可替换该对象，但不能取消真实扩展验收 |
| 企业私有 / 云端 Agent | 通过现有云端委派合同及专用适配器接入其任务、状态和结果接口；仅有模型对话 API 的服务仍归模型连接，不包装成完整执行 Agent |

默认选择遵循“任务明确选择 → 个人在该项目的偏好 → 当前企业内的个人默认 → 企业默认”，企业允许范围和任务必需能力先行过滤。配置默认值只影响新执行；正在运行和恢复中的执行固定 Agent、版本、账号绑定、工作目录与模型来源。首选 Agent 不可用时保留输入，说明缺少什么并让用户恢复或明确选择替代，不偷偷改用另一个 Agent 或账号。

统一的是工作台的任务与交互合同，原生能力按实情保留。适配器声明安装 / 登录、模型来源、流式输出、原生命令 / 工作模式、工具与批准、历史列举 / 读取 / 恢复、文件 / 附件、Skill / 连接器绑定、取消及用量等能力；不支持的操作明确阻止或提供有说明的人工路径。原生账号未提供额度或用量时显示未知，不能显示为免费或零消耗。具体接口与所有权见[架构中的 Agent 适配](architecture.md#多-agent-适配与执行绑定)。

同一 Agent 的恢复使用原生会话标识；改用另一 Agent 时创建新的执行记录和原生会话，通过用户核对的任务目标、材料版本、已有产物、约束及未决问题接续同一 Work Item。不得移植隐藏推理、账号、缓存或假定不同 Agent 的上下文格式兼容。存在未确认的外部动作时先核对回执；同一目录中的旧写入执行未结束前，不让新 Agent 接管写入。

Skill / Loop 声明任务所需能力和经过验证的执行器版本；可移植指令与专属工具绑定分开。换 Agent 前检查依赖和权限，不能把原生配置文件原样复制给另一 Agent，也不能把“安装了 Skill”当成它已能执行。

## 2. 场景推演：以完成工作为终点

以下是设计用的假设场景，不是已访谈或已验收的客户事实。M1 用客户授权样本核对规模与业务规则，M6 用真实使用结果验收。

| 场景 | 员工实际路径 | 容易被忽略的问题 | 必须出现的结果 |
| --- | --- | --- | --- |
| 售后客服：群聊里反映漏发 | 选取微信记录和照片 → 选择客户 / 订单 → 查订单与物流 → 云端提出方案 → 主管审核补发 / 退款建议 → 客服回复、记录处理 | 昵称重名、照片未解析、旧承诺冲突、金额由模型猜测、重复退款 | 引用原文的事项；金额来自业务规则；批准绑定版本；写入回执；回复未发送时明确标记 |
| 客户成功：多轮需求交接 | 多批聊天与附件 → 人工归入同一事项 → 补齐影响范围 → 云端分析 → 转给负责同事 → 客户确认 | 多批覆盖不完整、不同客户混入、交接后无人负责 | 保留各批来源、未决问题、负责人和期限；接手人无需读取整段私人会话 |
| 运营：本地表格对账 | 选择两份表格 → 检查格式 / 范围 → 本地整理 → 授权上传必要字段 → 云端匹配 → 返回差异表 → 人工确认后写回 | 大文件阻塞、公式与原表丢失、上传全盘、网络中断后重复提交 | 原文件不被无声覆盖；可打开的差异表；可查询的提交和写入回执 |
| 主管：持续跟进异常事项 | 分配负责人和截止时间 → 定期由云端检查 → 仅有新情况或需要批准时提醒 | 本机睡眠导致漏任务、提醒刷屏、任务已撤销还执行 | 云端有持久化计划；本地显示实际状态；撤权 / 取消被执行端落实 |
| 交付人员：接入第二个客户 | 安装同一包 → 企业登录 → 安装该客户能力包 → 接入验收服务 → 完成业务任务 | 写死租户和 API、复制客户端分支、插件升级损坏旧任务 | 无客户端专属补丁；能力包版本可追溯；凭据、知识和诊断严格隔离 |
| 已有 Agent 偏好：客户 A 用 Claude Code，客户 B 用 Codex | 识别已有安装 → 选择账号与默认 Agent → 使用相同客服 / 文档方法 → 必要时交接同一事项 | 只换模型却不换执行器、强制安装 Pi、原生批准丢失、切换后重复执行或串账号 | 同一客户端尊重不同默认值；实际调用所选 Agent；任务、方法和结果可核对，差异与限制可见 |

首个客服闭环细节由 [客服与微信桥](customer-service.md) 维护，不在本页重复协议。

## 4. 采用的产品经验及验收落点

这一节供开发评审使用；用户界面和产品介绍只描述 Turnsu 自身。Muse 指本次调研的 **Meta Muse**。以下来自官方资料的能力描述，没有做同负载竞品实测，不据此宣称内存、效率或安全优于它们。

| 参考优点 | Turnsu 的具体采用方式 | 阶段 / 可见证据 |
| --- | --- | --- |
| WorkBuddy：项目聚合规则、资料、能力与授权 | 企业工作空间预配置资料范围、可用方法和连接器，员工直接开始工作 | M1 / M2：首次登录可完成一项任务，无需先配协议 |
| WorkBuddy：本地与云端任务、多人接续 | 统一事项保留负责人、资料版本、云端回执；交接分享必要证据和结论 | M3：关机后云任务继续、另一成员可授权接手 |
| WorkBuddy：项目资产及个人 / 共享连接 | 企业资料版本与个人私有上下文分开，连接使用明确的身份和费用归属 | M2 / M3：换租户、撤权和协作不会借用他人的凭据 |
| Muse：持续任务与有分寸的主动提醒 | 持久化计划、活动记录、截止时间、预算；仅有进展或需人处理时通知 | M4：重开可继续跟进，重复事件不重复提醒 |
| Muse：主会话与独立主题 | 工作空间统一待办，事项有独立会话；后台工作可切走，返回仍知进展 | M4：多事项输入不互相覆盖、不混用材料 |
| Muse：可查看的活动、权限和记忆 | 每个事项显示实际动作；记忆可查来源、纠错、删除和设置作用域 | M4：纠错后下一次执行使用新版本，其他客户不受影响 |
| Muse：结构化批准与丰富结果 | 批准对象 / 动作 / 内容版本，文档、表格、差异和回复草稿直接可用 | M3 / M4：修改后的动作不能沿用旧批准；成果可核验 |
| Muse：执行与凭据 / 权限控制分离 | 授权由 Host 和企业服务强制执行，外部记录和 Skill 无权扩大能力 | M1–M5：越权工具调用和提示注入不能变成业务写入 |
| LinkCode：独立 Agent 适配器、统一事件和能力声明 | 在现有 Host 收敛执行入口，保留每种 Agent 的原生会话、工具与批准；上层按能力使用 | M1 / M2 / M5：三种既有 Agent 分别验收，第四种真实适配器验证扩展边界 |

来源：[WorkBuddy 企业版项目](https://cloud.tencent.com/document/product/1831/138797)、[WorkBuddy 远程任务](https://cloud.tencent.com/document/product/1831/134407)、[Muse 产品设计](https://introducing.muse.ai/)、[Muse 安全架构](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)。WorkBuddy 官方项目文档同时明确其本地任务仍使用云端推理；Turnsu 也必须如实展示模型与数据去向。

多 Agent 适配参考 [LinkCode 官方架构](https://github.com/arcboxlabs/linkcode/blob/master/docs/ARCHITECTURE.md)的适配器及历史能力分层；第四种扩展候选依据 [OpenCode 官方 SDK](https://opencode.ai/docs/sdk/)。本次只核对公开资料，未实际接入它们。实现优先复用现有 Host 和三种连接，不因参考而另起常驻宿主或替换业务控制层。

采用这些优点不要求复制完整对话历史、无限预加载、永久常驻全部 Agent，或新增头像养成、复杂计划视图与虚拟机平台。客户需要的是连续、可信地完成工作。用户反馈的 WorkBuddy 内存现象尚未被本项目归因；本项目按自己的进程与负载测量。

## 5. 六个迭代及退出条件

每个迭代同时实现必要的状态、错误恢复、交互与回归，不把安全、资源和恢复全部留到最后。范围所有者是模块责任，实际人力在开始时分配；这里不默认启用并行代理。

### M1：企业入口、多 Agent 适配与可控执行基础

**依赖：** 用户确认本计划；取得一个可用企业验收空间及模型连接。主要责任：`apps/desktop`、`packages/agent-host`、`packages/contracts`、`services/product-api`。

- 企业邀请 / 登录、配置下发、工作空间切换与撤销；复用现有身份和项目权限。离线保留有效期内已授权本地工作，高影响动作在线复核；不假装离线时实时获知撤权，也不承诺召回已导出的资料。
- 将现有 Pi / Claude Code / Codex 接入收敛为适配器注册与能力合同，补齐发现、健康状态、原生登录引导、统一执行事件、批准和恢复；保留原生工具及特有能力，不重写其推理循环。
- 企业设置允许使用与默认的 Agent，员工可以保存个人 / 项目偏好；尊重已有安装及账号。没有环境时按企业选定的已验证执行器准备依赖，逐个核验可分发版本、工具限制及两平台运行，不指定 Pi 为所有客户默认。
- 受管工具从选定目录读写、文档处理及批准的连接器开始；不暴露任意 shell 或无限网络作为默认能力。若某原生执行器不能服从该边界，只能进入明确标注的自带 Agent 模式。
- 模型网关沿用现有连接模块，增加企业配置、健康状态、费用 / 额度归属。验证实际协议、流式响应、工具调用、超时、限流、取消和鉴权失败；不新造一套 LLM 网关服务。
- 定义一个持久业务事项与多次执行的映射；已有本地会话可关联，云端 Work Item 为共享业务状态所有者。先落恢复点、失败状态与资源观测。

**退出：** 在干净 macOS / Windows 用户环境中，非开发者不使用终端即可进入企业空间，通过引导完成企业选择的环境准备和原生登录、执行本地文件任务并重开继续；原有安装、账号配置和历史保留。Pi / Claude Code / Codex 分别完成真实新建、执行、批准边界、停止和本工作台会话恢复。两个企业配置可选择不同默认 Agent，个人偏好按企业隔离。公司网关按各执行器实际支持的协议验收；未安装、未登录、版本不兼容和 Host 异常有恢复入口。提交逐 Agent / 版本 / 平台的能力矩阵和全进程基线。

### M2：材料、微信桥与受控适配包

**依赖：** M1 的作用域、事项和执行边界。主要责任：`packages/agent-host`、`packages/agent-runtime`、`packages/contracts`、`apps/desktop`；微信接收变更由 `turnsu/wechat-bridge` 持有。

- 本地文件与桥归档统一成有来源、版本和覆盖说明的材料；原件、派生文本与模型选用片段分开保存。支持 TXT / CSV、XLSX、DOCX、文本 PDF；扫描 PDF / 图片识别、语音转写通过可选连接器启用，未启用或失败时显示未解析。首个客服包需验收真实图片凭证的已配置识别路径，不能只测文字；格式不支持时保留原件。
- 开发工作台微信桥消费者，明确导入选择、重复交接、原档被清理、篡改和部分解析路径；复用桥协议，不复制应答 UI。Windows 提供用户主动粘贴及授权 TXT / ZIP / 附件文件导入，不假装拥有原生微信分享扩展。
- 增量文件观察、有界补扫、按需解析、分块上传和下载校验，移除常驻全目录读文件算哈希的负载来源。
- 最小企业能力包包含固定版本的 Skill、连接器、配置 schema 和权限要求；安装前检测依赖、签名 / 发布来源与兼容性，失败原子回退。先完成微信导入与一个业务连接器，不建设公共插件市场。
- 通过同一适配边界完成第四种真实 Agent（默认 OpenCode）的接入验收：允许增加专属适配器、依赖声明与注册，任务 UI 和客服业务流程不新增厂商分支；支持范围写入同一兼容矩阵，不能用模拟适配器证明可扩展。
- 支持受控网页检索 / 下载及表单草稿；域名和下载材料受企业策略约束。发布、提交或外发必须走对应的批准与回执，不能以“浏览器可操作”视为业务系统已接通。

**退出：** 两平台可导入授权材料、查看原文和覆盖范围、关联客户与事项；macOS 使用真实微信导出批次进入工作台，Windows 用真实授权导出文件进入相同后续流程。重复打开不重复建单、调用模型或计费；解析失败保留原档；不同租户不串资料。大归档不会阻塞输入与切换，恶意压缩包被拒绝。第四种 Agent 用真实任务验证扩展合同；安装、升级或卸载适配器 / 能力包不损坏现有任务，已卸载的执行器不会被自动替换。

### M3：云端往返与客服完整闭环

**依赖：** M2 材料与连接器，公司的真实云端任务接收 / 查询 / 结果接口。主要责任：`services/product-api`、`packages/product-client`、`packages/agent-host`、`apps/desktop`，云端业务适配由对应服务持有。

- 基于现有 Work Item、outbox 和结果审核实现“提交—接收—运行—补充信息—结果—审核—交付”；本地网络请求成功不直接视为云端业务接收。
- 交接固定材料版本、允许动作、预算、期限、身份和回调关联；云端拉取范围受控。事件有游标与去重，断线可补读；关机重开查询已有任务，不重建执行。
- 客服具备客户 / 订单关联、事实与未决问题、负责人、截止时间、查询结果、候选回复和审批。至少接通一个客户已有订单 / CRM / 工单服务，敏感动作遵循它的确定性规则。
- 人工审核回复及承诺；微信个人聊天默认复制后人工发送。业务系统写入必须返回回执；不支持幂等或结果查询的接口在结果未知时交人工核对，不自动重放。
- 结果可接受、退回或继续补充；退回产生新执行并关联原结果。取消传播至云端和执行者，明确已发生副作用无法自动撤销。
- 验证同一事项在不同 Agent 间通过资料接续，或交给使用另一 Agent 的同事 / 云端执行者：记录执行归属、允许资料、费用和回执；成员的账号与原生会话不共享，借用其执行环境必须另有明确授权。

**退出：** 使用授权客服资料和真实业务验收环境，完成从微信记录到客户事项、云端查询 / 处理、人工审核、回复和业务结果的全过程；订单事实、来源及写入回执可核对。用获授权测试会话完成实际人工发送并标记人工确认，按业务规则关闭事项或留下待跟进，不能停在生成草稿。断网、云端超时、重复回调、修改审批内容和成员撤权时没有重复业务写入或越权。云端任务在客户端离线后仍推进，需补资料时原事项可继续。

### M4：日常使用、持续工作与 Skill OS

**依赖：** M3 闭环稳定；主要责任：`apps/desktop`、`packages/agent-host`、既有 Skill / Loop 服务与团队 Web 管理界面。

- 打磨首次进入、加载、搜索、草稿、文件与结果预览、错误恢复和通知返回；保留主导航极简。主管通过事项负责人和待确认筛选处理工作。
- 长任务的计划 / 检查点复用已有执行控制；本地运行与云端运行有明确标识。调度、重试和提醒有截止时间、预算、静音和撤销；不轮询加载所有历史。
- 记忆先做可审核的事实、偏好与业务知识引用，绑定来源、租户、客户和有效期；纠错 / 删除使后续检索与缓存同步失效，不保存隐藏推理。
- 从真实完成任务提取 Skill 草稿，用户检查后试跑与发布。Loop 保留简明步骤、依赖、停止 / 恢复及结果核验；方法更新不隐式替换执行中任务的版本。
- 客户能力包可按角色展示，管理员能查看已安装版本、依赖、授权、更新差异和回退；普通员工不会看到底层配置表。
- 新建任务显示实际 Agent 及默认来源，可直接改选或管理连接；继续历史优先恢复原执行器，更换时预览交接资料。Skill / Loop 显示当前 Agent 的兼容状态和缺失依赖，不以模型名称替代 Agent 标识。

**退出：** 非技术客服和运营分别独立完成任务；可以切换多个事项、处理等待批准、返回后台结果并找到依据。修改记忆和停用方法影响正确范围；通知不重复、不刷屏。真实任务沉淀的方法在新任务中可复用，失败位置和恢复动作清楚。

### M5：可靠运行与正式发行

**依赖：** M1–M4 受影响真实路径已通；签名、设备与发行环境可用。主要责任：桌面发布、Host / runtime、服务端及验证负责人。

- 跑完整进程组的长时、冷启动、附件和多任务负载；限制本地并发、解析进程、缓存、日志和磁盘占用。检查退出、休眠 / 唤醒、崩溃和网络变化。
- 三种首批 Agent 及第四种扩展分别验证支持的平台、账号、升级与能力差异；同一平台的资源预算覆盖所有由工作台启动的 Agent。仅发现安装不启动每个执行器，不为每种适配器分别放大总并发和缓存上限。
- 正式签名、macOS 公证及 Windows 发行验证；一个明确的更新所有者，支持分批更新、失败回退、数据库迁移备份和兼容检查。
- 微信桥与工作台适配器按需配置为兼容版本，每个组件只有一个更新所有者。工作台不打包第二套应答运行时，不与已有桥争抢分享注册和数据目录；具体共存验收见客服协议页。
- 管理员能看到设备 / 组件版本、连接状态和故障定位信息；用户预览并同意后导出脱敏诊断。保留范围、撤销、费用额度、依赖更新与漏洞修复进入运营流程。

**退出：** 以下发布门槛逐项取得与发行版本相符的证据；失败的关键路径修复后重验。正式包可在干净机器安装、从上一支持版本升级、失败后恢复，资料 / 凭据 / 草稿 / 执行关联不丢失；不使用开发证书或编译成功代替可分发证据。

### M6：两个客户的交付与可复用性验收

**依赖：** M5 候选发行包，两个获授权的客户环境和相应业务接口。主要责任：产品、交付、核心研发与客户验收人员共同确认。

- 客户 A 覆盖客服与微信材料，客户 B 覆盖本地文档 / 表格及云端协作；至少包含普通员工与主管两个角色，使用同一客户端版本。验收必须覆盖至少两种不同的客户默认 Agent；客户偏好相同时另设授权配置补验，不强迫客户为验收改变日常偏好。
- 每个客户连续至少 5 个工作日按真实工作使用；授权样本、服务请求、人工修订与失败恢复可核对，不将内置示例或自动化测试当作客户反馈。
- 只用插件、Skill、配置及云端服务完成差异适配。需要改客户端核心时先判断是否通用缺口，通用修复回到同一版本，不创建客户分支。
- 交付安装 / 恢复指南、支持的平台与格式、能力包清单、费用和数据说明，以及责任与故障反馈入口；不把业务使用门槛转嫁为技术安装教程。

**退出：** 两客户确认主路径可日常使用，失败可以理解和恢复；公司能独立安装、升级和排障。剩余限制不破坏已承诺范围，并向客户明确。至此才可称本轮完整版本交付。

## 6. 发布门槛与测量方式

下面数值是**待实施验证的目标，不是当前成绩**。M1 固定机器、数据集、计时起止与统计方法；若证据显示目标不合理，先说明原因和用户影响再调整，不能验收失败后静默放宽。内存按各平台的进程驻留集总和统计（共享页可能重复计数），另外记录可获得的私有占用；同平台采用同一口径比较，不把不同平台的计数差异包装成优化。

| 范围 | 发布门槛 |
| --- | --- |
| 平台 | macOS 14.4+ 的 Apple Silicon / Intel，Windows 11 x64，16 GB 内存参考机器；每类真机完成核心路径。Windows ARM、Windows 原生微信分享、手机微信直接桥接不在本次支持承诺内 |
| 首次使用 | 无开发工具的普通用户账户可安装、企业接入、准备受管环境并产出真实结果；步骤、下载体积和耗时有实测记录 |
| 多 Agent | Pi / Claude Code / Codex 在两平台分别验收发现、登录、真实执行、批准边界、停止、重开与结果；第四种真实适配器按声明平台验收。能力表标出原生历史、Skill、工具、模型协议和用量的支持差异，不能靠 Pi 通过或 mock 通过统一标绿 |
| 偏好与交接 | 企业默认和个人偏好持久化且隔离；实际启动所选 Agent / 账号。故障不静默换 Agent；同事项跨 Agent 接续不串会话、重复写入或泄露私有上下文，原执行记录和结果始终可追溯 |
| 资料 | 验收至少覆盖 50 MiB 单文件、200 MiB 解压后批次、跨批 100,000 条文字记录；按格式测试，容量不等于全部可解析。超限预检说明边界，不静默裁剪；原始文件与解析结果可分开查看 |
| 大量历史 | 10,000 个事项 / 会话、100,000 条消息的固定数据集；启动不读全量正文或恢复所有 Agent，翻页不累积无限 DOM |
| 响应 | 应用冷启动至可操作 P95 ≤5 秒，本地已有数据的事项切换 P95 ≤1 秒；网络、首次安装依赖、解析分别呈现真实等待，不能遮掩成本 |
| 内存 | 完整工作台进程组空闲目标 ≤500 MiB；所有 Agent 合计的本地重任务并发默认 1、可配置上限 2，双任务典型负载目标 ≤1.5 GiB。计入 Renderer、主进程、Host、所有由工作台启动的 Agent、解析和桥接子进程，按 Agent 分别出曲线；用户在工作台外自行启动的进程单列说明，未提供本地模型不计入模型权重 |
| 长时 | 8 小时持续任务与切换、睡眠 / 唤醒后回到相同空闲场景；等待回收 10 分钟，相比预热基线增长不超过 max(15%, 100 MiB)，无持续增长趋势；同时记录峰值、CPU、磁盘与完整进程明细 |
| 故障 | 上传 / 接收 / 执行 / 写入任一阶段中断可恢复；重复请求和事件不重复写入；无法确认的动作进入人工核对；取消与撤权阻止后续未执行动作 |
| 数据 | 跨租户 / 客户越权失败；原档哈希一致、时间与来源可查；索引、记忆和云端副本的删除 / 保留策略有效；日志和诊断不包含密钥及默认聊天正文 |
| 安装与更新 | 正式签名、公证 / Windows 安装验证、同身份升级、故障回退、兼容迁移以及插件回退；确认用户数据完整；无多余常驻进程或重复微信分享入口 |
| 模型与业务 | 实际公司网关的推理 / 工具 / 取消、实际云端任务与业务系统回执；模拟依赖只能用于回归，不能关闭这一门槛 |
| 可用性与交付 | 中文输入法、键盘、焦点、缩放、可读错误、通知返回；两个客户按 M6 使用同一发行包，具备支持与恢复交付材料 |

长时测试不能解释其他产品的内存原因，也不能把关闭一个进程造成的下降当作任务安全恢复。需要同时检查持久化状态与继续执行结果。

## 7. 排期、依赖与范围控制

依赖顺序为 **M1 → M2 → M3 → M4 → M5 → M6**。资源与安全约束从 M1 开始，M5 集中做完整发行验证。正式结果不由文档数量或测试数量衡量。

在“2 名核心研发、可持续投入的测试 / 交付人员、两个客户配合且业务接口已有”的假设下，建议预留 **12–18 周**作为完整交付的规划窗口；这是基于当前差距的工程估算，未获得团队产能和接口联调证据，不是承诺日期。M1 结束按真实接入和设备结果重估每阶段，并保留全部发布门槛。签名、公证、客户接口和验收样本未就绪的等待需单列，不能算成代码已完成。

该窗口现在需同时容纳三种正式 Agent 的完整验证与第四种扩展。M1 按适配器实际差异重估工作量；当前保留规划窗口作为假设，不宣称新增范围没有排期影响，也不能为守住原估算将多 Agent 降为后续可选项。

实施前需落实：企业验收租户和网关、客户 Agent 偏好及获授权测试账号 / 版本、获授权客服样本、一个真实业务系统接口及其回执能力、两平台测试设备、发行证书与更新托管、第二客户和验收责任人。这些是后续实施依赖，本轮无需为了写计划操作客户数据、申请系统权限或安装组件。

范围变化只在用户目标、真实接口或平台证据推翻本计划时提出。一般实现选择由研发在上述边界内完成；遇到难点不能以新增框架、展示页、模拟回执或改验收条件代替解决实际路径。
