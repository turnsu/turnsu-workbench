# Turnsu 本地 To B 工作台交付计划

**版本口径：通用本地 Agent 工作台。** 客户可不接入 Turnsu 云端、企业租户、CRM 或订单系统，直接在自己的电脑上完成项目资料处理。团队共享、云端复杂任务和业务连接器是按客户授权启用的扩展，不能成为本地版首次使用或发布验收的前置条件。

这份计划描述同一发行包的可用性门槛，不把构建、接口存在或模拟测试写成已交付。当前证据与缺口以[验证记录](verification.md)为准。

## 用户与黄金路径

企业员工打开或创建本地项目，选择或导入文件，选用已安装并已登录的 Codex、Pi、Claude Code 或 OpenCode，描述任务并处理原生权限请求，在项目中核对实际结果文件，再次打开工作台时继续同一会话。把有效做法沉淀为 Skill；需要顺序复用时才使用简明 Loop。客服人员可额外主动导入微信桥交接，在本地核对原文与解析覆盖，再让 Agent 整理回复草稿；发送和业务写入仍由员工或授权系统完成。

本地执行不等于离线推理。所选 Agent 连接远程模型时，输入可能按它的账号和模型配置发送给对应服务。工作台必须清楚展示 Agent 与模型来源，不替用户推定数据可外发。

| 员工要完成的事 | 可见完成证据 | 失败时的恢复 |
| --- | --- | --- |
| 接入已有 Agent | 实际选中的 CLI 创建原生会话；模型和登录错误可解释 | 保留任务草稿，不静默换 Agent 或账号 |
| 处理项目资料 | 原件仍在；导入副本、引用快照、Agent 产出在项目中可打开 | 单文件失败明确列出，重试不覆盖既有文件 |
| 多轮任务 | 流式回答、工具活动和原生批准可见；停止后状态真实 | 原生 ID 固定，重开后核对不确定结果再继续 |
| 查看历史 | 项目内搜索、索引和消息分页；大量会话仍能切换 | 数据库和会话文件保留，Host 异常可重新打开 |
| 复用方法 | Skill 可发现、使用、试跑和保存；Loop 不阻挡普通任务 | 不兼容的 Agent / 权限明确说明 |
| 客服资料 | 主动选取的桥归档有原文、来源、覆盖和未解析项 | 导入不自动分析、分享或发送；原档校验失败可重选 |

## 本版必须收口的工作

1. **四种 Agent 的真实执行路径。** 分别验证发现、登录引导、原生会话创建、模型选择、流式结果、权限、停止、重开恢复和进程退出。OpenCode 采用 ACP；不能以握手或模拟事件替代真实模型回合。Agent 无能力时说明限制。
2. **本地资料与成果。** 项目文件选择和受限文本引用保留发送时快照；从系统文件选择器导入普通文件，保留原件并避免同名覆盖；文本可预览，常用成果可由系统打开，其他格式可在文件夹定位。Agent 写文件后用户能核对真实文件。大文件、链接、目录变更及部分导入有明确状态。
3. **会话与内存。** 启动不加载所有会话正文；索引、消息、资料按需读取，闲置原生进程回收，执行中和待批准进程保留。以 Host、Renderer、Electron 主进程和原生 Agent 的完整进程组测量长时间运行，记录工作负载和平台，不用单次 Host RSS 推断整机结果。
4. **Skill OS 与极简 Loop。** 工作台与 Skill OS 是主导航。方法使用、从真实结果整理、试跑、版本和失败恢复可操作；Loop 默认只呈现输入、步骤和结果。方法不能自行提升工具权限。
5. **交付安全与恢复。** Electron 隔离渲染器、窄 IPC 与系统凭据存储保留；安装/升级不丢既有本机 SQLite、草稿和 Agent 原生历史。模糊执行结果不能自动重跑。只对用户明确选择的材料调用模型或共享。
6. **发行与实际使用。** Linux 开发机承担无图形构建和协议测试；macOS 与 Windows 分别用真实用户环境完成安装、中文输入、文件选择、Agent 登录与任务、文件打开、睡眠/重启恢复、卸载/升级和长时资源检查。未经设备验收不得标记为正式跨平台客户版。

## 验收顺序与当前状态

| 门槛 | 当前状态 | 退出证据 |
| --- | --- | --- |
| 本地项目、会话、草稿、分页与按需连接 | 已有实现；合成历史及 Host 测试通过 | 真实 UI 切换和重开任务 |
| Codex、Pi、Claude Code | 已有私有 Host 接入 | 各自使用真实账号完成一次文件任务、权限和恢复 |
| OpenCode | Linux 真实 CLI 已完成模型回合、项目文件读写、Host 重开续跑及自定义网关模型识别 | macOS / Windows 权限、停止和文件结果可见路径；公司网关真实推理 |
| 本地导入和成果打开 | 本轮代码与 Host 测试已接入 | macOS / Windows 文件对话框与系统默认应用实测 |
| 微信桥客服材料 | macOS v1 主动交接消费者已有合成验收 | 真实微信分享和原档到本地草稿的可见路径 |
| Skill OS / Loop | 已有项目 Skill、整理与试跑能力 | 非开发者从真实任务完成复用 |
| 桌面发行与资源 | Linux 构建及 macOS / Windows CI 无签名打包通过；实机交互与整机资源证据缺失 | 签名包、升级恢复、长时全进程组记录 |

即使没有企业租户、客户接口或真实客户数据，上述本地验收仍可用自有授权样本和临时项目推进。缺失真实 Agent 账号或目标系统设备时，对应条目保留“未验收”；不能通过伪造配置、静态演示或更改文案消除缺口。

## 客户适配与云端边界

同一桌面包服务不同客户。客户差异放在项目级 Skill、可选连接器、模型/Agent 配置与显式团队连接中；普通本地任务不要求管理员先下发企业策略。客户已有 Agent 账号与原生配置归客户所有，工作台不复制密钥和私人历史。工作台不承诺控制自带 Agent 的全部原生工具；需要强受管执行时，应在有真实企业策略与执行环境后单独验收。

Product API、共享 Work Item、云端 Agent、业务连接器与审批体系保留为可选扩展。启用时仍须服务端授权、版本固定、幂等回执和明确的数据共享；当前缺少验收租户和业务接口，不把 CRM 写入、云端客服闭环或两个客户上线宣称为本地版已完成。微信桥的原生分享入口由桥仓库负责；工作台负责主动消费和后续本地工作，详见[客服与微信桥](customer-service.md)。
