# Native Manual Review Checklist

本文把 native macOS App 的人工 review 路径拆成可勾选步骤。它的目标是让人工验收继续推进，同时避免把 Accessibility、AppleScript、屏幕录制或外部浏览器自动化变成默认前提。

## Entry

无权限构建入口：

```bash
scripts/review-loopops-native.command
```

该脚本只做三件事：

- 构建最新 debug app bundle。
- 复跑 native no-permission action wiring。
- 打印 app bundle 路径和本 checklist 路径。

它不会调用 `open`，不会关闭旧进程，不会启动系统浏览器，不会调用 AppleScript、Accessibility 或屏幕录制。

当前人工打开路径：

```text
.build/debug-app/WeChatIntelligenceRadar.app
```

如果你希望我执行系统级点击或截图验收，需要走 `12-remaining-decision-contract.md` 里的 native pixel-click 授权路径；本 checklist 不把那件事伪装成已完成。

## Review Map

| Path | What to click manually | Expected visible result | Automated evidence |
| --- | --- | --- | --- |
| Workbench Review Guide | 打开 app 后停在 Workbench，看 `Review Guide`，逐条打开 `Loop Library`、`Skill OS`、`Knowledge`、`Chat Control`，再勾选 checklist | guide progress 从 `0/4` 逐步到 `4/4 checked`，导航切换不丢当前 run context | `workbench_review_guide_paths=true`、`workbench_review_guide_checklist=true` |
| Evidence map | 在 Workbench `Review Guide` 里找到 `Evidence map` | 显示 Marketplace listing、Knowledge and toast、Tool builder logs、Triple quick GUI 四个来源；每行说明 applied 和 check | `workbench_evidence_map_sources=4` |
| Agent team traceability | 在 Workbench `Review Guide` 里找到 `Agent team traceability` | 显示 8 个模块，从 Marketplace/Loop Library 到 Agent team process；每行都有 research、implementation、evidence 摘要 | `workbench_traceability_modules=8` |
| Review decision | 在 Workbench `Review Guide` 里找到 `Review decision`，切换 `Set pending`、`Mark needs work`、`Mark approved`，编辑 Blockers 和 Notes | 状态能在 pending / needs work / approved 间切换；blockers 和 notes 明确保留 native pixel-click 授权边界和人工 review 备注 | `workbench_review_decision_board=true` |
| Manual review record | 在 Workbench `Review Guide` 里找到 `Manual review record`，点击 `Prepare record` | 状态从 `Pending human review` 切到 `Ready to record`；显示 `Saved locally`、完整 command preview、`scripts/record-loopops-review.command` 和 Markdown/JSON record artifacts | `workbench_review_record_handoff=true`、`workbench_review_record_preview=true`、`workbench_review_state_persistence=true` |

## Product UI Pass Criteria

人工 review 时按 product register 判断，不按 marketing page 标准判断：

- 默认首屏是可工作的 Workbench，不是说明页。
- 导航稳定表达 `Workbench`、`Loop Library`、`Skill OS`、`Knowledge`、`Studio`。
- 列表像 database rows：可扫读、细分隔、行 action 明确；不是一屏营销卡片。
- 详情页有 metadata、readiness、required inputs、knowledge/tools、example task 和 primary action。
- Chat quick GUI 靠近输入框，scope 明确，model/search/temporary/attach 不抢主层级。
- Toast 和 setup receipt 不遮挡主要任务，不替代持久状态。
- 可见文案不暴露 provider、runtime、worker、artifact path、schema field、secret。
- 长中文任务、英文 skill id、market symbol 能截断或换行，不重叠。
- Light/dark 都保持可读；颜色不是唯一状态表达。

## Recording Results

人工 review 后把结果追加到 `08-evidence-receipts.md`，建议格式：

```text
native_manual_review_date=YYYY-MM-DD
native_manual_review_app=.build/debug-app/WeChatIntelligenceRadar.app
native_manual_review_checked_paths=workbench,library,skill-os,studio,knowledge,run-chat,review-chat

```

如果出现权限弹窗，先记录触发动作和弹窗文案。不要继续扩大权限范围，除非用户明确同意进入 `12-remaining-decision-contract.md` 的 pixel-click hardening path。
