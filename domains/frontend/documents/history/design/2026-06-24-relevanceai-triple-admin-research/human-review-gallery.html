01 Workbench default

Check that the first screen is a working operations surface with Review Guide, Active Queue, Run Result and Run Chat.

02 Loop Library database

Rows should feel like a Notion/RelevanceAI database, with clear run, open, readiness, ledger, packet and share-safe actions.

03 Workbench Run Result

Starting a loop should create an active run, with Final Answer, Review Packet, Tool logs, Knowledge and Run Chat scoped to that selected run.

04 Skill OS stack

Skill OS should present user-facing skills, tools and stacks, without provider, runtime, worker, artifact, schema or secret wording.

05 Skill OS add to stack

Adding a skill should update the ordered execution path while keeping the detail pane readable and toast feedback unobtrusive.

05a Create Tool import modal

Default, Invent and Import starting points should be visible. Tool name, task description, input scope and Start action should be clear.

05b Tool Logs validation

Use validation should produce readable failed and draft logs with status, source, duration, cost, output and Review Chat handoff.

06 Studio contract page

Contract structure should stay visible while editing. Execution path, structured fields, save-state and reset/review controls should remain coherent.

06a Builder patch receipt

Builder Chat should update steps, ordered skill path, review rule, exit condition and output shape, with a receipt explaining what matched.

06b Studio review changes

Review changes should identify changed blocks without hiding the contract. A lightweight block diff is acceptable for this iteration.

07 Knowledge new menu

Blank, Upload file, Import from website and Integrations should map clearly to the RelevanceAI Knowledge menu pattern.

08 Knowledge setup panel

Blank creation should open an editable setup panel with title, note content and save action visible.

08b Knowledge source detail

Saved source should appear as reusable context with detail metadata visible, not only a toast.

09 Chat quick GUI

Chat should be compact and scoped. Model, Instant/Deep, Search, Attach, Temporary and prompt category controls should stay close to the composer.

10 Workbench empty state

Empty queue should be useful and recoverable, with a clear run action and seeded review restore.

Live click checks

Use the running review URL after the visual pass.

  • Run one ready Loop from Loop Library, then run 2-3 loops and switch active queue rows.
  • Open an unready Loop and verify it routes to Studio setup instead of launching a run.
  • In Skill OS, open Create Tool, switch Default, Invent and Import, fill fields, start, then open Use and Logs.
  • Drag or add a skill into Studio execution path, reorder, remove one item, save, then reopen.
  • In Builder Chat, send a structured instruction with steps, skill path, review rule, exit condition and output shape.
  • In Knowledge, create a source, attach it to latest run, switch runs and confirm the attachment does not leak.
  • In Chat, send Run Chat and Review Chat messages and confirm transcripts stay scoped.
