# App Interaction Brief

## Surface Model

Use a three-region native workspace:

- Sidebar: workspace navigation.
- Content: list, page, editor, or result.
- Inspector: selected object details, scoped chat, logs, or settings.

## Primary Areas

### Workbench

- Active queue as a native list or table.
- Selected run opens a detail page.
- Final Answer, Timeline, Evidence Gaps, Review Packet, and Run Chat stay in one run-scoped workspace.
- Multiple running loops keep independent progress and selection.

### Loop Library

- Loop, template, ledger, and share-safe log lists.
- Row selection opens detail.
- Row menu exposes Run, Open, Duplicate, Edit, Archive.
- Multi-select enables batch actions in toolbar or bottom action area.
- Detail page shows readiness, required inputs, skill path, review state, and recent runs.

### Skill OS

- Capability list for skills, tools, extensions, stacks, and logs.
- Drag skills or stacks into Studio execution path.
- Detail inspector shows setup, examples, used-by loops, and recent logs.
- Configure, Add to Loop, Add to Stack, and Open Logs are visible actions.

### Studio

- Left shelf: skills and stacks.
- Center: Loop Contract form and ordered execution path.
- Right: Builder Chat and proposed change receipt.
- Execution path is reorderable and supports disable/remove/open detail.
- Save remains explicit.

### Knowledge

- Source library with freshness, extraction state, attached targets, and activity.
- Attach popover requires target selection: run, loop, or builder chat.
- Confirmation uses native banners or compact notifications.

## Interaction Details

- Keyboard focus should follow selection and visible panels.
- Context menus should be available for repeated list actions.
- Sheets should be used for short creation/configuration tasks.
- Full pages should be used for loop editing, stack editing, and result review.
- External actions should use explicit confirmation only when the action would leave the local product boundary.
