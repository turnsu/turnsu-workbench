# Turnsu 工作台

Turnsu 工作台是面向企业客户的本地 Agent 工作入口。员工在自己的项目中处理资料和任务，按需把明确授权的工作交给团队服务；企业可以在同一客户端上配置不同的 Skill、连接器与执行 Agent。

产品主路径是：打开项目 → 选择材料与执行 Agent → 完成或交接工作 → 核对结果及来源 → 决定是否共享、回复或提交业务动作。工作台不把导入资料、模型推理、上云和业务写入混为一次操作。

## 当前能力

- **本地工作与恢复**：项目、会话、历史和草稿保存在本机；会话索引和历史按页读取，闲置 Agent 连接自动回收。
- **多 Agent 入口**：接入用户已有的 Codex、Pi 与 Claude Code。新任务可临时选择 Agent，并保存个人或项目默认值；已有会话继续使用创建时的 Agent，不因偏好变化而迁移。安装发现不代表已经登录或具备工具权限。
- **模型连接**：可以沿用原生 Agent 配置，或配置兼容的模型网关；工作台区分 Agent 与模型来源。网关密钥使用操作系统的加密存储。
- **微信桥资料**：macOS 用户主动选择一份交接后，可以预览解析覆盖、校验原档大小与 SHA-256、导入当前项目的本机私有快照，并按页引用记录到本机任务。导入本身不调用模型、不自动上云、不发送微信消息；未解析媒体保持未解析状态。
- **Skill OS 与可选团队协作**：整理和使用已发布的工作方法；在明确连接团队后使用现有共享项目、事项、结果审核及交接能力。私有原生会话和企业共享事项保持不同的所有权。

当前仍在完整迭代中。企业统一配置和受管 Agent 安装、第四种执行器、Windows 文件导入、客服订单 / CRM / 工单连接、云端复杂任务闭环、签名发行与多客户验收尚未完成。不要把已有本地导入或模拟测试当作这些能力的验收。计划、边界与证据见[完整迭代计划](wiki/roadmap.md)、[系统架构](wiki/architecture.md)及[验证记录](wiki/verification.md)。

## 开发与验证

需要 Node.js ≥22.19。各包使用自己的锁文件；原生 Agent CLI 由使用者安装并登录，工作台不会覆盖其全局配置。

```sh
npm run setup
npm test
npm run build
```

`npm start` 运行桌面开发版本，`npm run package` 生成桌面包。桌面基于 Electron、React 和隔离的 Node Host；团队服务独立部署。日常构建与自动测试可以在 Linux 开发机的隔离环境进行，无需在个人 Mac 上反复安装应用。最终的 macOS / Windows 交互、Agent 登录和发行包仍需对应系统的真实验收。
